# ADR-001: Use a Relational Database

## Status

Accepted

## Context

The Internal Operations Service Hub stores structured and related data such as Users, Departments, Request Types, and Requests.

The system also needs to keep relationships consistent, such as:
- which User created a Request
- which Department a Request belongs to
- which Department a Request Type maps to
- which Department a Department Staff user belongs to

## Decision

- Use one relational database for the system data.
- A relational database fits the current requirements because the data is structured and has clear relationships.
- The choice of specific relational database engine (e.g. PostgresQL, MySQL) is deferred to a future ADR.

## Consequences

- Relationships between Users, Departments, Request Types, and Requests can be kept consistent.
- Request ownership and department routing can be represented clearly.
- The data model stays simple and easy to understand.
- The system depends on one main database for its stored data.
- The system uses one main database. If the database is unavailable, users cannot read or save requests. This is acceptable for the current scope, but backups should be considered later.
